1. Dữ liệu Memory được lấy từ file nào trong folder Memory?
Dữ liệu (MemFree, MemAvailable, App PSS) của Memory được lấy từ file từ file `*_start_*.txt`  như trong `memory_main.py`
CÒn dữ liệu Pageboostd được lấy từ Pageboostd\pageboost_main.py
2. Cấu trúc file Memory như thế nào? 
- File có format giống `/proc/meminfo`  
(Ví dụ format file  *_start_*.txt`: 
MemTotal:        5517856 kB
MemFree:          190892 kB
MemAvailable:    2209324 kB
Buffers:           17952 kB
Cached:          2455616 kB
SwapCached:       239984 kB
Active:           839792 kB
Inactive:        1882752 kB
)
Các key cần extract: `MemFree`, `MemAvailable`, `App PSS` 
3. Thời điểm lấy dữ liệu Memory?
- `MemFree MB (before launch)` = Lấy từ file `*_start_*.txt`?=
- `App PSS` = Lấy từ file dumpstate (file .txt có dung lượng lớn nhất trong .zip) (Tham khảo logic lấy PSS cho từng app của sheet Testing_App_PSS_Comparison trong file MemoryStatus\app_start_kill_analyzer.py)
- `MemAvailable` hay đã có sẵn trong file *_start_*.txt`
4. Làm sao map file Memory với trace file tương ứng? 
Cách map:
File trace: A266MYL2_BOS_6GB_85_251229_1S_251229_104822_camera.log
File *_start_*.tx: A266MYL2_BOS_6GB_85_251229_1S_251229_103945_camera_Start_LogFile
Giả sử có 3 cycle Camera thì sẽ có 3 file *_start_*.tx  chứa thông tin của Camera cho 3 cycle này, và trong tên của file có timestamp xuất hiện tăng dần
Một app với mỗi Cycle trước khi chạy sẽ có thông tin Memory tại file *_start_*.txt` xuất hiện tăng dần theo thời gian và khi chạy entry và reentry sẽ có Bugreport.zip (trong .zip chứa file dumpstate)
Và thứ tự các file *_start_*.txt` xuất hiện theo thời gian tương ứng với file log trace
5. Nếu có nhiều cycle (entry/reentry), file Memory nào tương ứng với cycle nào? 
Một file *_start_*.txt` thể hiện Memory của app đó trước khi chạy (entry + re-entry) 
Ví dụ: A266MYL2_BOS_6GB_85_251229_1S_251229_103945_camera_Start_LogFile sẽ tương ứng cho cả A266MYL2_BOS_6GB_85_251229_1S_251229_104822_camera.log (entry) và A266MYL2_BOS_6GB_85_251229_1S_251229_104840_camera.log (re-entry) của Cycle 1
6. Dữ liệu Pageboostd lấy từ đâu?
Dữ liệu Pageboostd lấy từ Pageboostd\pageboost_main.py, logic trong file này xử lý.
Ví dụ: app Clock được mapping = comsecandroidappclockpackage và regex detect trong dumpstate của Cycle 1
12-29 08:08:44.265  1000  2995 11060 E pageboostd: alp end : app comsecandroidappclockpackage data_amount 35433800
-> giá trị pageboost của cycle này là 35433800
7.  Cấu trúc dữ liệu Pageboostd? 
File dumpstate dạng .txt , đọc hiểu logic của Pageboostd\pageboost_main.py để nắm rõ hơn
8. Câu hỏi 8: 
Vì pageboostd lấy từ dumpstate, mà dumpstate nằm trong Bugreport.zip nên mỗi Cycle sẽ có 1 data pageboost cho mỗi app trong cycle đó.
Trong file dumpstate_parser có define 6 group và các app trong mỗi group đó
Ví dụ: A266MYL2_BOS_6GB_85_251229_1S_251229_110118_2part_Bugreport.zip là group 2, sẽ có các app là   2: ['hello', 'call', 'dial', 'clock']
Dumpstate sẽ có thông tin pageboostd cho 4 app này
9. Hiện tại LoadApkAssets đã có trong bảng (phần sau) 
Vì query SQL đang lấy tổng các loadApkAsset, không phân loại nên cần phải viết lại query SQl để tách riêng 3 loại này, từ đó mời fill đúng phần được.
Về phần loadApkAsset này, hãy tạo sẵn function để trống đó, tôi sẽ viết query và lấy data. Ví dụ query sẽ phải truyền tham số là loại (system_server, system_ui, launching_app), 
và hàm sẽ gọi lần lượt các tham số này trả về data tương ứng cho mỗi loại. Khi có data tương ứng sẽ truyền vào bảng excel của phần LoadApkAssets
10. Làm sao xác định LoadApkAssets của từng process?
Dựa vào function query tạo mới trong sql_query, tôi sẽ tạo phần này sau. Hàm này sẽ trả về một dict dạng {"system_server" : 100, "system_ui" : 120, "launching_app" : 130}
Việc của bạn là sử dụng data từ hàm này trả vê để dùng 
11. `UpTime` là gì? Lấy từ đâu
- Từ tracename sẽ biết đang chạy app gì, mapping được thuộc group nào (giả sử group 2: ['hello', 'call', 'dial', 'clock']. Trong file .zip này có dumpstate file
và tại dòng 2 của file sẽ là == dumpstate: 2025-12-29 08:10:48, Uptime chính là 2025-12-29 08:10:48
12. Trong dumpstate crash được bắt regex (FATAL EXCEPTION, am_anr) Tạm thời hãy tạo hàm gọi và để trống đó, hàm này tôi sẽ tự implement, để tra về số lượng cho từng cycle. 
13. Hiện tại Binder Transaction đã có trong bảng Statistics (cuối file)
Giữ nguyên cả 2 chỗ, vừa vào phần mở rộng bảng sequence, và hiển thị tại phần cuối file excel Static
14. `Compiler| Speed| speed profile` là gì
Đọc logic xử lý sheet Compiler_Comparison của file  MemoryStatus\app_start_kill_analyzer.py
Đây là 3 loại của loại Complier. Detect được từng loại này và fill cho phù hợp cho từng app tại từng cycle
15. `App kill by| empty #17, empty #17` là gì?
Đọc logic sheet tạo App_Start_Kill_Analysis của file MemoryStatus\app_start_kill_analyzer.py cột DUT Kill Reasons
16. `App start by| broadcast, content provider` là gì?
Đọc logic sheet App_Start_Kill_Analysis, cột DUT Start Reasons
